# Cas de recette

Quatre dossiers fictifs, dans des métiers différents, pour vérifier le comportement de l'app après chaque modification des consignes (`prompts/`). Chaque fichier donne les champs à saisir à l'étape 1, puis le résultat attendu.

| Cas | Fichier | Ce qu'il vérifie | Scénario du cahier de recette |
|---|---|---|---|
| 1 | [cas-1-comptable.md](cas-1-comptable.md) | Bonne adéquation, offre reçue à négocier | R05 |
| 2 | [cas-2-formation.md](cas-2-formation.md) | Reconversion, adéquation faible | R06 |
| 3 | [cas-3-maintenance.md](cas-3-maintenance.md) | Évolution interne | R07 |
| 4 | [cas-4-commercial.md](cas-4-commercial.md) | CV lacunaire : aucune invention (RG01) | R08 |
| 2 bis | Cas 2 avec une prétention de **50 k€** au lieu de 38 | Prétention hors marché : badge « Hors marché », montant à viser dans la fourchette, ancrage qui ne reprend pas les 50 k€ | R24 |

Après une modification, rejouez au minimum le cas le plus proche de ce que vous avez changé. Le cas 4 est à rejouer après toute modification de `regles.md` ou de `lecture.md`.

Tous les profils et toutes les offres sont fictifs.
